## Module: impact map

Each repository keeps a small system map (components, data flows, displays, registrations, operations). Every Tier 1+ change carries an impact inventory derived from it plus a search for consumers: each point is `adapt` (with a check), `untouched` (with a reason), or `follow-up` (with a started session). Acceptance runs every `adapt` check. When replacing a component, rehearse in shadow first and keep a bit-identical way back.
